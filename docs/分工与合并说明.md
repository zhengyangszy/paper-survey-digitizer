# 分工与合并说明（组员操作手册）

**中文** | [English](member-guide.en.md)

> 一句话流程：**①组长生成问卷结构 → ②每人认领一批照片 → 识别+审核 → ⑤导出批次 CSV → 组长合并 → 互换复核**。

## 0. 组长做一次：生成问卷结构（① 区）

1. 粘贴 `.qes` 文本（变量名、字段类型、题目文本）；
2. 把**一份完整示例问卷**（已填过的真卷）按页序拍照，照片整批选入——
   页数会自动按照片数定下来（可手改）；
3. 点"生成 survey.json"：系统先按 .qes 确定性解析（变量名一字不动），
   再让 AI 对照照片校对题序并给每题写识别提示，产出**人工校验清单**；
4. **组长必须核对校验清单**（变量名与 EpiData 一字不差、选项编码一致），
   确认无误后打便携包发给组员。

## 1. 一次性准备（每人自己电脑做一次）

**方式 A（推荐，什么都不用装）**：组长发的「问卷数字化工具-便携版.zip」解压到任意位置，
双击文件夹里的「启动问卷工具.bat」，浏览器自动打开 http://localhost:3000 即可。
首次使用点右上角 ⚙ 设置，选厂商预设并粘贴**你自己的 API Key**，保存后显示"识别引擎 就绪"。

**方式 B（自己装环境）**：安装 Node.js LTS（https://nodejs.org ），然后：
2. 拿到项目文件夹，在项目文件夹打开命令行（文件夹地址栏输入 `cmd` 回车），执行：
   ```
   npm install
   copy .env.example .env
   ```
3. 用记事本打开 `.env`，把 `OPENAI_API_KEY=` 后面换成你自己的密钥，保存。
4. 启动：`npm start`，浏览器打开 http://localhost:3000 。看到"识别引擎 就绪"即可开工。

## 2. 分批规则

- 组长把问卷材料按人分文件夹：`张三_0001-0050`、`李四_0051-0100`……
- **每人只处理自己那批**，不需要账号权限，各人的数据存在各自电脑上。
- **支持的文件类型**：照片（jpg/png）、扫描 PDF、Word（.docx）都可以——
  浏览器自动转成页图片再归组（本地转换，材料不经任何服务器）。
- **归组规则**（决定一份问卷是哪几页）：
  - 所有患者**整合在一个 PDF / 一叠照片**里：按页序自然排序，每"每份页数"张
    自动切成一份（页数看 ⚙ 设置，通常由组长生成 survey.json 时按示例定下）；
  - **一人一个文件**：同样规则，每个文件的页按序切分；
  - 显式命名 `编号_p1.jpg、编号_p2.jpg` 按编号归组（优先级最高，页数不齐的问卷用这个最稳）；
  - 同编号同页码重传 = 覆盖旧图（拍糊了重拍重传即可），不会产生重复。
- **问卷编号查重**：把编号设为 EpiData 里的一个变量，在 ⚙ 设置里选"问卷编号变量"
  ——识别后系统自动查重：同一编号出现两次 → 列表和审核页标红
  （说明重复拍摄或归组错了，导出前必须处理）。

## 3. 每人的日常操作

1. **上传**：② 区选择你那批的全部材料（PDF/Word/照片混着选也行，系统自动转换归组）。
2. **识别**：点"③ 识别所有未识别问卷"。系统自动：压缩图片 → 分块并发调用模型 → 合并。
   字段多的问卷（上百个变量）每份约 1-2 分钟；多份同时排队并发处理，请等"完成"出现，
   失败的份再点一次识别按钮即可重试。
3. **审核**：④ 列表点"审核"进入审核页。左边是原图（**多页问卷用左上角 ◁ ▷ 翻页**，每页都要核对），
   右边是整份问卷的识别结果表单：
   - **标红的字段**是模型没把握的（置信度低于阈值），必须对照原图逐个核对修改；
   - 没标红的字段建议抽查（识别不是百分百对）；
   - 核对完点"✓ 标记已确认"，"下一份 →"继续。
   - 建议在"审核人"框填自己名字（会记住，写进导出记录，方便互换复核时追溯）。
4. **导出**：全部确认后，⑤ 区填批次号（组长分配，如 `zhangsan01`）和审核人，点"导出 CSV"。
   - 文件名形如 `zhangsan01_张三_20261028.csv`，审核人/批次在文件名里，CSV 内只有 EpiData 变量列。
   - 每确认满 50 份（可配）系统会提醒你导出一批，**别攒到最后一次导**。
5. **上交**：把 `data/exports/` 里的批次 CSV 发给组长（微信/网盘均可）。

## 4. 组长合并

方式一（推荐，不用开网页）：把收到的所有批次 CSV 放一个文件夹，
```
node scripts/merge-csv.js 总表.csv 张三_0001.csv 李四_0051.csv 王五_0101.csv
```
方式二：打开网页，⑤ 区"选择文件"选中所有批次 CSV，点"合并为总 CSV"。

**合并自带保险**：任何文件的列名/列顺序和第一个文件不一致会直接拒绝合并并报错——
这说明有人用了不同版本的 survey.json，必须先解决再合并，绝不静默拼错列。

## 5. 互换复核（质量抽查）

- 合并后，组长把总表按人切开发回：**张三审李四的批次、李四审王五的**。
- 复核方式：CSV 每行对应一份问卷，复核人拿原图（在对方电脑 `data/images/` 里，
  建议批次上交时连同图片文件夹一起拷给复核人）抽查，重点看文字填空列。
- 发现错误：在对方电脑上改（或让对方改）该份问卷并重新导出批次；改动过的批次**重新导出后要重新合并**。

## 6. 导入 EpiData

- 最终 CSV 的列名就是 EpiData 变量名、顺序与 .qes 一致，直接用 EpiData Import 数据功能导入 .rec/.epx 即可。
- 合并前各批次**行序即问卷序**（按上传顺序），如需按问卷编号核对，上传时用问卷编号命名图片文件（如 `0001.jpg`）。

## 7. 三个纪律（踩坑代价大）

1. **不要手改 CSV 的列名或列顺序**——合并会拒绝，EpiData 会错列。
2. **survey.json 是唯一的结构定义**。发现变量名/选项编码有错，改 .qes → 重新 `npm run qes` → **所有人重新导出**，不要只改自己那份 CSV。
3. **每批次导出后备份**（拷 `data/` 整个文件夹），识别可以重跑，审核劳动不能丢。
